# step 192 — вид, Expando, раскладка по именам, удобный слой труб

Задание 1 мастер-агента: читать сообщение без класса (`View`), копировать его в
`Expando` и в свой класс по именам (`Into<T>`), и удобный слой над трубами
(`Pipe.Read/Write`, `foreach`, `Regions`, `Where`, `WriteTo`, `ToHeap`).
Прогоны — QEMU. Закоммичено вместе со step 193 (один коммит).

## Исходное состояние

- База: `fe1995f` (step 191) + незакоммиченное исправление массивов
  перечислений (генератор `ArrayElementName`, `MessageCatalog.RegisterArray`
  с типом элемента, проверки в `PipeTests`, autorun 201).

## Решения по заданию

- Фрагменты целевого кода — независимые сценарии; писатель и читатель в разных
  образах (ядро / приложение).
- Ответы мастера: свой тип `View`; `IDictionary` только у `Expando`; чужой блок
  проверяется один раз при приёме; стадии — обычные лямбды; частичного перевода
  нет; расхождение типа при чтении с классом — отказ, по именам — явно `Into<T>()`.

## Ход работы

### 1. Основа: описания, проверка блока, вид, копии, удобный слой (код)

- `TypeKeys.Field.Enum`, `Description.EnumNames/EnumValues` — имена членов
  перечислений в описании, не в ключе; формат схемы трубы дополнен (поле — имя
  перечисления, описание — члены). Генератор: `RegisterEnum`, аргумент enum у
  полей и элементов массивов.
- `Exchange/RegionShapes.cs` — схема трубы, разобранная один раз: формы типов,
  поля по имени, род поля (примитив / ссылка / структура на месте), проверка
  правдоподобия схемы (поле внутри объекта) и `Validate` блока: ключи описаны,
  записи в границах, каждая ссылка — ноль или начало записи блока.
- `Pipes/View.cs` — `readonly struct View`: поля по имени, элементы, длина,
  перечисление полей, `Has`, `Kind`, `TypeName`; `Expando` под видом читается
  по своим записям; операторы сравнения с числом, строкой, `bool`, видом;
  `true/false`; явные приведения; неявные из примитивов и строки (значение для
  записи / сравнения); запись значений и `null` с проверкой рода и диапазона;
  `ObjectDisposedException` после конца региона (`ViewScope`).
- `Pipes/ViewCopy.cs` — `ToExpando` (глубокая копия, общие ссылки и циклы
  сохраняются, структура std с тем же ключом — сама собой) и `Into<T>` (план
  «поле источника → поле приёмника» на пару типов, кэш; расширение чисел без
  потерь; несовместимость — исключение с именем поля при построении плана).
- `Pipes/PipeLoops.cs` — `Pipe.Read<T>/Read/Write<T>`, `PipeException`,
  `foreach` по читателю (регион шага отпускается, выход из цикла закрывает
  читателя), `Regions`, `Where`, `WriteTo` (типизированный — `Move`; по виду —
  блок как есть, без перевода, с описанием и корневым ключом входа),
  `Into<T>()` у читателя, `Dropped`, `ToHeap()` у любого объекта сообщения
  (`Region.ToHeapFrom` — копия графа под объектом).
- `Region.Resolve` называет ключ, которого нет; типизированный читатель
  называет расходящийся вложенный тип по описанию писателя.
- Регрессия: короткий пакет 201/201, печать журнала по новой схеме.

### 3. Проверка: девиртуализация у получателя (вопрос владельца)

Вопрос: тип, который образ только принимает (труба, `Into`, `ToHeap`) и сам
не создаёт через `new`, — не свернёт ли ILC вызовы на нём к «известным»
реализациям, не выбросит ли методы, не свернёт ли `is` в `false`?

- Детектор (тест 19): `DevirtA/B/C : DevirtBase, IDevirt` в std; ядро создаёт
  только B, приложение — только A; B приходит по трубе, C — через `Into`.
  Объект прогоняется через непрозрачный метод. Результат: `is`/`as`, вызов
  через базу и через интерфейс у B и C — свои (207/B/2, 307/C/3). **Бага нет.**
- Почему: в `.ilc.rsp` ядра и приложений нет `--scan` (сканера всей
  программы) — ILC не знает множества созданных типов и не девиртуализирует по
  нему. Карта ILC (`IlcGenerateMapFile`, разово): `DevirtB`, `DevirtC` и даже
  абстрактный `DevirtBase` — `ConstructedEEType`; 986 созданных против 12
  «необходимых» (неупакованные структуры, несколько массивов).
- Скрытый риск: включение `--scan` сделает дыру настоящей; тогда генератор
  должен давать ILC факт создания каждого `[Message]`-класса. Тест 19 —
  сторож.

### 4. Анализатор: вид и переменная цикла привязаны к шагу

- Привязаны к региону шага: любое значение типа `View`; переменная цикла по
  читателю (`foreach (T e in reader)`, `… in reader.Where(…)`,
  `foreach (Region<T> m in reader.Regions)`). Вынос в поле, статик, чужой
  массив, `[Retains]`-параметр, замыкание, возврат — SOSR002/004.
- Привязку снимают пользовательские приведения из вида (к числу, `string`,
  `Expando`), а также `ToHeap()` и `Into<T>()` (результаты методов не
  отслеживаются). Переменная цикла `Regions` не считается утечкой (SOSR005):
  регион отпускает цикл. Запись через индексатор вида — не SOSR006 (вид
  проверяет её сам).
- Код самой библиотеки (`SharpOS.Std.Pipes`) — механизм, правила его не
  проверяют (прагма в `PipeLoops` снята).
- Хостовые тесты: 55/55 (+8: вид в поле, вложенный вид, `[Retains]`, возврат,
  лямбда; сообщение цикла в поле; регион цикла в статике; корректный код —
  копии, `Expando`, `Into`, `ToHeap`, запись через вид). Сборка ядра и
  приложений — без срабатываний.
- Дополнительно к тестам 13–18: `Where` в цикле и `Where(...).WriteTo(...)` у
  типизированного читателя; `foreach (Expando x in Pipe.Read(...))`.

### 5. Полный пакет: находка — тест 1 ядра разбирал описание на каждое поле

- Первый полный пакет: 234/234 во всех батареях, кроме одной: тест 1 (журнал)
  не уложился в 10 с ожидания вердикта (ядро доделало позже). Утечки нет
  (перепись кучи колеблется). Причина — старые помощники теста `ReadInt` /
  `ReadString` / `FieldAt` в `PipeProbe` разбирали **всё описание трубы на
  каждое чтение поля**; описание — весь каталог писателя, выросший в шагах
  191–192. Переписано на вид (разбор один раз на трубу), помощники удалены.
- Счёт батареи — 234 (в первой оценке было 236).
- Замер под `--gc-stress 1 1` в `--pipe-stress`: вид работает (медленно, как и
  положено под сборкой на каждом выделении).

### 6. Сверка с заданием — закрытые пробелы

- SOSR007 (новое правило): `ToHeap()` на типе вне каталога — ошибка сборки
  («нет сообщения, в котором он лежит»). Хостовые тесты 56/56.
- Тест «`Into<T>()` с классом самого писателя» — те же объекты в своей куче.
- Тест `ToHeap()` вложенного объекта (`r.Where.ToHeap()`) после шага и сборки.
- `WriteTo` у вида: труба-приёмник несёт описание и корневой тип входа —
  ядро читает её **со своим классом** (`PipeReader<KernelReport>`, сверка типа
  как обычно) и видит новые значения и тот же адрес блока.
- Запись на переменной `foreach` настоящего `View` (не только параметр лямбды).
- Полный пакет до этих правок: `ran=13 failed=0`, 234/234 ×3, стресс чистый.

## Отчёт по заданию 1

**Сделано** — все шесть разделов: вид (чтение, сравнения, приведения, запись
значений и `null`, `ObjectDisposedException`, проверка блока при приёме,
таблица полей на тип, имена членов перечислений в описаниях); `Expando` из
вида (глубокая копия, общие ссылки и циклы); `Into<T>` (у вида и у читателя,
план на пару типов, расширение без потерь, исключение при несовместимости);
удобный слой (`Pipe.Read/Write`, `foreach` с закрытием читателя, `Regions`,
`ToHeap()` у любого объекта, исключения, `Dropped`, `Where`, `WriteTo`);
анализатор (вид и переменная цикла привязаны к шагу, SOSR007); тесты 1–12.

**Тесты** — `AotTests` 13–19 (+35 проверок, 236 всего), ядро — `PipeProbe`
16–20 и читатели 23–25; хостовые 56/56.

**Отступления:**
- Запись во временный вид (`v["A"][0] = 1`) — CS1612, нужна переменная
  (образец задания так и пишет).
- Замеры (тест 12) — только QEMU TCG: ноутбук в автономном режиме не трогаем.
  Поле ~0.7–0.8 мкс, `Into<ReportLite>` 50–100 мкс, `ToExpando` 160–240 мкс
  на отчёт из 22 полей.
- `WriteTo` у вида подключает выход при первом прошедшем сообщении (схема и
  корневой ключ входа известны только после первого приёма); если ничего не
  прошло — выход не создаётся.
- Под видом значения из `Expando` пишутся только в существующие упакованные
  поля того же рода (новое имя — исключение).

**Находки по ходу:** девиртуализация у получателя — не воспроизводится (ILC
без `--scan`), тест 19 — сторож; тест 1 ядра разбирал описание трубы на
каждое поле — переписан на вид.

**Не сделано** (вне шага): `dynamic`, два приложения одновременно, AST/планы,
`Select`, `await foreach`, скорость перевода, частичный перевод.
