## Вариантный interface dispatch

**Симптом.** DOOM панично падал на переходе между уровнями:
`iface-resolve: no impl slot`, получатель — массив (6 интерфейсов), в карте
запрошенного интерфейса нет.

**Как искали.** Воспроизведение оказалось важнее рассуждений. Сначала я
предположил attract-режим (демо на титуле) — неверно: падает именно переход
на следующий уровень, экран статистики между картами. Затем предположил, что
у пользователя старая версия без патча step142 — тоже неверно, `aa4c238`
содержит патч. Оба раза поправил пользователь.

Дальше — прямой замер. Панику перевели из `Shutdown` в `Halt`
(`BootSequence.Phase0`), чтобы QEMU оставался жив и память читалась; сняли
через QMP `memsave` четыре MethodTable и сравнили:

```
REQUESTED     genDef=0x1000B4D68   arg=0x1000C0690
ifaceMap[5]   genDef=0x1000B4D68   arg=0x1000C8CB8   ← то же определение, другой аргумент
```

То есть запрашивают тот же generic-интерфейс, что уже есть в карте, только с
другим аргументом типа, а `arg` записи карты — это `related` получателя, тип
элемента массива. Ковариантный доступ, подтверждённый данными.

**Раскладку взяли из исходников, а не из головы** — по подсказке
пользователя, в `gc-experiment/dotnet-runtime-8.0` лежит нужная версия
(образ собран ILC 8). Это сразу поймало ошибку моей реконструкции по
памяти: в порядке хвостовых полей есть `DispatchMap`, который я пропустил.
На интерфейсных MT он отсутствует, поэтому смещения случайно сошлись, — на
типе с картой диспатча чтение было бы тихо неверным.

**Что сделано.** В `GcMethodTable` — корректный обход хвоста и аксессоры
`GetGenericDefinition` / `GetGenericArgument` / `GetGenericVariance`
(арность — `ComponentSize` определения; при арности 1 аргумент лежит в самом
поле композиции, при большей — относительный указатель на список; вектор
вариантности живёт на определении). В `FindImplSlot` — ветка
`InterfaceMatchesWithVariance`, порт `TypeParametersAreCompatible`.

**Осознанно консервативно**, потому что цена ошибки несимметрична: неверное
совпадение не упадёт, а тихо вызовет не тот метод. При отсутствии вектора
вариантности, арности вне `1..8`, значимых типах в аргументах и вложенной
вариантности внутри проверки присваиваемости — отказ, то есть прежняя паника.

Три ранее пропатченные таблицы ManagedDoom (`MapTitles`, `AnimationInfo`,
`WorldMap`) оставлены как есть: они корректны и без вариантности.

## Курсор в лаунчере

Движок XtermSharp давно понимает DECTCEM (`ESC[?25l/h` →
`Terminal.CursorHidden`), а наш рендерер флаг игнорировал. Теперь
`TerminalConsole.DrawCursor` его учитывает, а лаунчер гасит курсор в меню и
возвращает перед передачей экрана дочернему приложению и на выходе.
Побочно это заработало и для PSReadLine, который штатно прячет курсор на
время перерисовки строки.

Грабли по дороге: escape-последовательности в C#-исходник надо писать как
`"\x1b[?25l"`. Первые правки положили в файл сырой байт `0x1B`, а попытки
заменить его через shell не срабатывали — обратный слэш схлопывался до
вызова интерпретатора, и ESC «заменялся» сам на себя.

## Обвязка репозитория

- Реестр «Известные проблемы и временные ограничения» вынесен из README в
  `limits.md` (рядом с `donext.md`), ссылка добавлена в `donext.md`. Таблица
  тиров и компаративная таблица фич остались в README — сначала я вынес и их,
  пользователь поправил.
- **Исправлены неверные отметки по рефлексии** в компаративной таблице.
  Стояло 🚫 «архитектурно невозможно» с обоснованиями «AOT strips metadata» и
  «требует JIT». Для `Reflection.Emit` и DLR это верно, а вот
  `Reflection runtime metadata`, `Activator.CreateInstance(Type)` и
  `Type.GetType(...)` в NativeAOT достижимы: конструктор уже скомпилирован,
  JIT не нужен, нужны метаданные и слой `System.Reflection`, которых у нас
  просто нет. Переведены в 🔴.
- `wads/` теперь сохраняется на чистом клоне (`wads/*` + `!wads/.gitkeep`) —
  прежнее правило `wads/` игнорировало каталог целиком, и `.gitkeep` в него
  положить было нельзя. Нужно для секции «Как запустить», которая кладёт туда
  WAD через `curl`.
- В «Отдельное спасибо» добавлены XtermSharp (MIT, вендоринг) и `shitty`
  (MIT + GPL-3, корпуса тестов терминала).

## Что осталось

- В `ReportResolveFailure` не печатается адрес вызывающего. Пока вариантность
  закрыта, это не горит, но следующий отказ резолвера снова придётся искать
  сравнением MT вместо прямого указания на метод.
- Паника теперь halt, а не shutdown: после аварии QEMU надо гасить вручную
  (`run_build.ps1 -Stop`). Плата за читаемую посмертную память.
