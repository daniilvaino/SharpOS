## Что сделано

**`KernelHeap` — корзины (`OS/src/Kernel/Memory/KernelHeap.cs`).**
- **Списки блоков.** Общий список в порядке адресов остался для склейки соседей, но поиск по нему больше не ходит. Свободные блоки лежат ещё и в 32 корзинах по размеру: [16·2^b, 32·2^b). Связи хранятся в полезной части свободного блока, головы корзин — в `.bss` (куча стартует в Phase 1, до статиков). Заголовок прежний, 24 Б.
- **Выделение.** Своя корзина, не больше 8 проб, иначе голова корзины выше, которая заведомо больше запроса. Дальше остаток своей корзины, потом рост.
- **`Free`.** Проверяет блок за O(1): указатель в пределах регионов, выровнен, соседи ссылаются на него. Склейка — один шаг в каждую сторону.
- **`Alloc`** под try/finally вокруг `Suppress/Allow`.
- **Строка роста:** `heap grow pages: N blocks=… free=… allocs=… probes=…`.

**Кэши диспетчеризации (`InterfaceDispatchResolver.PublishCache`).**
- **Переиспользование.** Кэш — это только (интерфейс, слот, тип, цель), поэтому одинаковые больше не создаются. Таблица по содержимому с открытой адресацией в сырой памяти `KernelHeap`.
- **Безопасность.** Кэши по-прежнему не освобождаются (читатель мог взять старый указатель), но их число ограничено различными четвёрками.

**Строки ядра — в управляемой куче (`std-no-runtime/StringRuntime.KernelHeap.cs`).**
- **Путь.** `FastAllocateString` берёт из `GcHeap` тем же путём, что `RhNewString`: сборщик их видит и освобождает.
- **Когда остаётся `KernelHeap`:**
  - до `GcHeap.Init`;
  - внутри критической секции `GcHeap` — новый флаг `GcHeap.InAllocator`, потому что рост сегмента идёт через `KernelHeap`, а её перепись печатает числа;
  - во время сборки (`GcMark.InProgress`).
- **Проверка.** Стресс-строки батареи (`--gc-stress 16 4`, `1 1`) — главный детектор строки, которую держит что-то невидимое сборщику. Прошли.

**Хвост сегмента (`std-no-runtime/GC/GcHeap.cs`, `RetireTail`).** Перед переходом на новый сегмент хвост старого `[Current, End)` становится обходимым свободным маркером. Если он не меньше 32 Б, он встаёт в список свободных. Маркеру нужен MT свободного объекта, а он заполнялся только первым подметанием. Поэтому `GcSweep.EnsureInit` открыт для `GcHeap`: хвост можно вывести из оборота до любой сборки. Действует и в приложениях.

**`PeLoader` без копии файла (`OS/src/Kernel/Pe/PointerRawFile.cs`, `PeImageLayout`, `PeLoader`).**
- **Разбор на месте.** `IRawFile` поверх неуправляемой памяти, только чтение: PeNet разбирает заголовки прямо в буфере кэша программ.
- **`PeImageLayout`** принимает `IRawFile`; версии с `byte[]` остались обёртками для проб.

**Мелочь:**
- `Stats[0]` не вычитает запасные таблицы страниц дважды: `TablePages` их уже включает;
- `HwFaultBridge`: восстановление обрезанного до 32 бит адреса — через `VirtualMemory.WindowBase` (`0x5000_0000_0000`), а не через `0x500_0000_0000`;
- `ProcessImageBuilder`: при неудачной сборке страницы стека возвращаются, в том числе выделенная, но не отображённая.

**PIPEPERF, проверка 7.** Поиск теперь меряется по четырём ключам (первый, четверть, середина, последний), берётся лучший. Причина — ниже.

## Поиск в Expando зависит от раскладки (под QEMU)

С `RetireTail` проверка 7 PIPEPERF стала стабильно проваливаться: поиск в куче на 256 записях — 450–580 нс в трёх прогонах подряд, остальные размеры — 125–150 нс. Без `RetireTail` — 145 нс.

Работа поиска от этой правки не зависит: те же инструкции, тот же ключ, а `RetireTail` меняет только, куда ложатся объекты.
- **Ключ.** Печать адреса искомого ключа показала середину страницы (`0xACC`) — не он.
- **Строка-имя записи.** Печать её адреса создавала строки и список, сдвигала раскладку — и замедление исчезало: 143 нс с `RetireTail`.

Вывод: под QEMU без ускорения одна и та же операция стоит в 3 раза больше при некоторых раскладках объектов. Цена обращения зависит от адреса (программный TLB, обращения через границу страницы). Какой доступ медленный, не найдено. Для этого нужна запись адресов без выделений или прогон на ноутбуке — записано в `donext`.

Замер поэтому берёт лучший из четырёх ключей. Поиск перебором по имени был бы медленным на всех.
